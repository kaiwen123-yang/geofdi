1. **高层数据 txt**：逐文件读前 200 行推断格式（分隔符、列数、表头有无、时间戳格式与频率）。**判定清单（逐项"有/无/待定"）**：IMU（四元数/陀螺/加计，频率）、footForce[4]、逐关节 motorState（q/dq/τ_est，20 电机还是 12）、机身位置/速度估计、步态/模式字段、时间基准（本地/UTC/GPS）。写健壮解析器 `io/go2_highlevel_txt.py`（容忍列数变体，未知列原样保留并命名 col_N）。**这一项决定 R⁻ 是全功率（关节通道）还是降级（足底力镜像 + IMU）——两条路都预先实现。**
2. **足部惯导 csv**：列结构、频率、装在哪条/哪些腿（从重力方向与摆动特征推断并记录推断依据）、与高层数据的时间对齐方式。
3. **Fixposition**：枚举各会话目录内容（文件类型），识别可解析的轨迹产品（FP_A-ODOMETRY / NMEA / bag），写最小解析器提取 位置/速度/姿态+GPS 时间；记录与高层数据的对时策略（若无共同时钟，用运动相关性对齐并给残差）。
4. 逐会话汇总表：时长、行数、各流频率、缺失/异常（断流、时间回跳）。
5. **生成元数据问卷** `docs/protocol/go2_session_meta_form.md`：11 行 × {场地, 地形, 负载质量与位置, 指令速度, 步态, 天气, 异常备注}，留空待用户填写；R2/R3 的条件匹配依赖它，未填前先按"同日=同条件"的弱假设跑并标注。
