## 1. Metadata repair flow (the "zenoh metadata" step)

`fix_metadata.py --check` reconstructs what `metadata.yaml` *should* say from the `.db3` files
(file list, per-file counts and time ranges, topic types, QoS strings) and compares — the cases
it repairs are a missing/incomplete `metadata.yaml` after an abnormal stop, file lists that no
longer match the copied files, DDS-style type names (`pkg::msg::dds_::T_`) from zenoh-bridge
recordings, and empty QoS strings. **Result for both bags: consistent — no repair needed**
(rosbag2 metadata v5, storage sqlite3, schema v3 / `humble`, ROS-style type names, QoS present).
Stock `ros2 bag info` (Humble) also reads both bags. The three `robots_dog_msgs/*` topics
(`/uni_heading`, `/rtk_pvh`, `/uni_best_nav`) need the vendor message package to *decode*
(inventory only lists them); everything else decodes with the pure-python `rosbags` typestore.

## 3. Key determination

* **Joint-state topic: present** — `/joint_shm_controller/joint_states`
  (`sensor_msgs/msg/JointState`) at **200 Hz** in both bags, with `position`, `velocity` **and
  `effort`** for **16 joints**: `fl1_hip_roll fl2_hip_pitch fl3_knee_pitch fl4_foot`, then `fr*`,
  `bl*`, `br*` — i.e. 3 leg joints + 1 **wheel** (`*4_foot`) per leg. This settles the open
  M1 questions in theory Part 0: **M1 is a wheeled-legged quadruped, n_j = 16 (12 leg DoF + 4
  wheel DoF), leg order fl, fr, bl, br, joint order (hip_roll, hip_pitch, knee_pitch, wheel).**
* **But there is no gait in these bags.** In both recordings the robot **rolled on its wheels
  for essentially the entire duration** with the legs held in a fixed crouch (hip_pitch ≈ ±1.85
  rad, knee ≈ ±1.6 rad): wheel joints spin at 9–13 rad/s (≈ 0.9–1.5 m/s at the ≈ 0.1 m wheel
  radius; odometry path 482 m at median 0.92 m/s, and 1183 m at median 1.27 m/s), the largest
  knee excursion inside any 1-s window is 0.27 rad (bag 1) and a single 0.62-rad transient at
  t ≈ 283 s (bag 2), median 0.02 rad; only the first ≈ 3 s of each bag are stationary. Fraction
  of 1-s windows classified as leg-stepping by the (generous) knee-swing > 0.15 rad rule: 9 s /
  530 s and 14 s / 955 s — all of them small posture adjustments while rolling, none a stride.
* **Verdict: swing-phase (gait) data does *not* exist in the legacy August bags.** Joint states
  are there, at the right rate, with torques — but they describe wheeled driving, not walking.
  The premise "joint-state topic present ⇒ swing-phase data already exists" fails on the
  locomotion mode. New walking sessions (Day-0 audit + nominal trot) are still required.

### 4a. Findings for the theory Part 0 TODOs (to be confirmed by the Day-0 mirrored-motion audit)

Static/rolling stance means over both bags (rad; fl, fr, bl, br): hip_roll (−0.52, +0.54,
+0.54, −0.53); hip_pitch (+1.87, −1.87, −1.92, +1.92); knee (+1.63, −1.66, −1.64, +1.63); wheel
velocity while rolling forward (−9.5, +9.6, −9.1, +9.3) rad/s. Under a laterally symmetric
stance the fl↔fr and bl↔br pairs therefore carry **opposite signs on all four joints** in vendor
coordinates: hip_roll flips as physics requires (s = −1), while hip_pitch, knee and wheel flip
too — i.e. the vendor defines mirrored positive directions for the pitch-axis joints (the case
anticipated in Remark *vendor conventions absorb signs*). Working hypothesis for
Table *tab:joint-signs* in vendor coordinates: **S_M1 = diag(−1, −1, −1, −1) for (hip_roll,
hip_pitch, knee, wheel)**, i.e. P_gs = Π_σ ⊗ (−I₄); front↔back also flips hip_roll/pitch/knee
but not the wheel. Effort signs follow the same pattern (knee |τ| ≈ 14–15 N·m in the crouch).
